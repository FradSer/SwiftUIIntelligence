# SwiftUIIntelligence chatbot document MVP

Users chat with an AI. The AI authors content and emits constrained document JSON. SwiftUIIntelligence validates complete documents and renders business-independent precompiled native SwiftUI Liquid Glass components. Follow-up messages revise documents, and new-topic requests can generate a different document. No OpenUI Lang, generated Swift, keyword business templates, or arbitrary execution.

Apple Foundation Models is the preferred real provider. Model-driven create/revise intent and guided content authoring precede guided document generation. Existing chatbot responses and a host-owned HTTPS backend can be injected. The default example is chat, not weather. Synthetic interaction fixtures and recorded real Mac outputs are distinctly labelled.

Scope: text, vertical/horizontal/grid layout, sections, lists, tables, callouts, metrics, icon lists, badges, numeric progress, line/area/bar/donut/radar charts and allowlisted host buttons; chat composer, context, loading, errors, invalid responses, retry, document replacement and JSON inspection. Native material implementation remains library-owned. Models may make semantic mistakes; strict JSON checks do not establish factual correctness.

The expanded goal requires three reactive examples through one generic component, state, and interaction protocol: equipment comparison, meal planning, and shared-meal splitting. Unseen categories, ingredients, people counts, and fields must work without scenario-specific pages or keyword routing. The host registers pure calculation capabilities. The AI selects authorized capability IDs, typed bindings, and generic layouts. Registration does not authorize external side effects. The user approves a generic instant parameter type for ISO8601 time points. It binds only to native date state and never requests calendar access or inserts a missing value. The user also approves bounded record collections for variable-length results. Each record has a stable ID and declared primitive fields. The user approves host-declared row-reference constraints in calculation input signatures. A text field can reference actual row IDs of another declared input parameter. Native generation authors target collections first and restricts reference candidates to their authored IDs. The host validates references without name matching, generated links, inserted values, or automatic repairs. Existing signatures and string-valued records remain compatible. Generic lists, tables, and charts select authorized collections and fields. No arbitrary nesting, property paths, or expressions are supported.

Bill splitting uses integer minor units in one currency. Items divide equally between selected participants. Service fees divide in proportion to allocated food amounts. The largest-remainder method assigns residual units, with stable participant IDs breaking ties. A nonzero item without participants blocks the final bill. Deterministic calculations belong to example hosts, not business-specific SDK components.

The user approves staged native generation to fit the available model context. The declaration stage now separates model-authored source data from explicit model-authored bindings. Registered signatures define required record-input slots. The user also approves scalar parameter role slots in native source generation. Each selected parameter contains a complete model-authored state declaration or an explicit reference to an authored ID. IDs, values, types and bounds remain model-authored. The library preserves declarations without value-based deduplication; a later AI call still authors public binding maps. After source validation, the binding call selects only existing compatible IDs. The host does not create binding-map entries, generate IDs, or add missing values. AI first authors state, source records, and calculation bindings. After declaration validation, AI authors generic layout referencing those IDs. The user also approves model-authored container trees with component slots, followed by individual component generation. The library substitutes validated authored components at their exact authored slots and preserves order. It does not add titles, pages, or default data. The user approves an internal native slot mode enum, static or records, because boolean guidance does not constrain component-mode pairs reliably. Text and control slots permit only static. The model explicitly selects the mode. The user also approves an internal model-authored purpose string for each component slot. The library passes it unchanged to that component call. It does not interpret purpose keywords, infer bindings, or add public document fields. Shape-only conversion maps it to the existing internal projected flag; public document JSON stays unchanged. Invalid modes reject rather than convert to a different choice.

Each component and the final document pass validation. Interaction stays disabled until complete acceptance.

The library only combines structures and validates the complete document. It does not insert missing values, apply business templates, or execute actions between stages.

Progressive rendering must validate each committed presentation boundary. Existing snapshot progress alone does not satisfy this requirement. Deliver independent host integration, three runnable examples, regression tests, actual runtime screenshots, and concise documentation. Distinguish live generation from recorded or synthetic evidence.

No model keys in client/source, private content in test runs, cloud resource creation, changes to Apple Intelligence/system/security settings, or public release. The user authorizes one private remote repository. No remote package URL or version tag is supplied. The complete original weather module is the GIF reference use case. Its six interactions and all visible modules remain preserved. A typed example-owned adapter expresses all reference data through generic SDK nodes; it is deterministic replay, separately labeled from actual model generation.
